Я использовал идею того, что хочу реализовать не просто по заданию, я приблизить к реальному решению в банках. А именно
в классе `SavingsAccount` есть метод `up_savings_balance`, которого не должно быть по заданию, но играет важную роль в 
решении.

    Когда человек открывает счет в банке, он кладет деньги сначала на расчетный счет, а уже потом на сберегательный. 
    Поэтому я использую этот метод для симуляции реальной жизни, где деньги не дублируются и там и там. Плюс хоть какое-то
    понятие транзцакий применяю (списание и пополение идут рядом).

Также я сделал файл `test.ipynb`, в котором прописаны "автотесты" для всех реализованных методов. Но хочу признаться,
так как по заданию это __не требовалось__, то я принял решение ускорить реализацию "автотестов" через использование ИИ.
